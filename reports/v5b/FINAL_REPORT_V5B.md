**Question (one sentence).** Does repairing the *labelled* data (author boxes + author negatives from new aerial/forest sources) and letting strong detectors collaborate (as teachers for a YOLO11m student, and as an ensemble at inference) improve recall at matched false-positive rate on held-out fixed-camera and aerial smoke, within one 24 h window and a 128-GPU ceiling?

**Decision 2 — ACCURATE mode: NOT shipped; kept as an optional demo mode only.** The calibrated A+B4+B6+B1 ensemble does not beat the best single model at matched FP on H2 (0.366 vs 0.388 @10%, 0.234 vs 0.287 @5%, 0.552 vs 0.553 @20%; below every YOLO under 5% FP) and H1 cannot rank it (different score scale, saturated at aerial confs), so the ">= 2 pt over the best single model on H1+H2" condition fails by −2.2 pt at the primary operating point. The mode stays available (`SMOKE_ACCURATE_MODELS`; the recipe is applied only with the 4-model set) to demonstrate per-model evidence, at 352 ms/frame on GPUs or 5.8-12.5 s/frame on CPU, and needs per-camera thresholds before any field use.

**Decision 3 — data arms, distillation, high-res: negative results; nothing from them is deployed.** B/C/D/D2/D3 are all below the control on H2 (−3.0 to −7.9 pt @10%); the teachers agree with the authors on labelled data (C 148 images, D 495 boxes, D2 408 boxes / 0 on FireMan) and D3's whole-plume pseudo-boxes on unlabelled footage do not help faint smoke (H2 0.358; VAL tiny@10% 0.113, the lowest) while raising pre-visible FIgLib alerts to 14/39; the 1920x1088 DINOv3-L is worse than its 1280 control at every FP level. The one robust gain from the new data — aerial recall (+21 pt on boreal VAL at 5% FP, all student arms) — is real, but it is not the deployed scenario and it arrives in the same checkpoint as the fixed-camera loss. **Core-story answer: NO — existing labelled smoke data + complementary models + teacher-student did not improve faint-smoke recognition on the frozen fixed-camera test; the best deployment candidate is the simplest one, the existing recipe at YOLO11m.**

Rule restated (pre-registered): FAST default (`expB`, `src/serve/config.py` defaults 0.05/0.30/0.15) is replaced only if a candidate beats expB on H2 R@10% by >= 2 pt AND does not lose on H1 image-level recall at matched FP AND passes `scripts/v5/test_shadow_service.py` + `scripts/v5b/test_modes.py`; ACCURATE mode ships only if S5 beats the best single model on H1+H2 by >= 2 pt — otherwise the single model is kept and the ensemble is reported. Independent of the outcome: ACCURATE requires per-camera thresholds on verified negatives (§4 threshold-transfer finding) and a GPU; the demo configuration (2-model `or` fusion at fixed-camera thresholds) is not a deployable recipe.

## 11. Limitations and honest non-results

- **Seeds: three for A and B only (A's seed 0 is replicate #4); C/D/D2/D3 and both B200 runs are single-seed.** The measured seed range is ±1.6 pt on sdis VAL R@10%, up to 30 pt on H1 at fixed-camera confs and 0.806-0.911 on ruokolahti — any difference smaller than that between single-seed arms is noise; the val->test rank reversal among students (B best on VAL, worst on TEST) is the live example.
- **H2 is a second opening** of the pyro-sdis TEST split (first at v4 close); the baseline values reproduce v4's and no threshold was tuned on it, but it is not a fresh set.
- **The FAST candidate's H1 margin is seed-fragile** (§8): the shipped checkpoint clears the H1 condition, one of its two seed repeats would not.
- **C and D are near-null by construction** (148 masked images, 495 pseudo boxes; D2 408). This is a finding about where pseudo-labels can act, not a failure of the teachers — but it means arms C/D cannot show much, whatever the test says.
- **D3's pseudo boxes are whole plumes** (median 25-36% of frame) on near-field/aerial material; they cannot teach faint fixed-camera smoke.
- **FireMan is presence-grade:** interpolated region boxes, one GPS-confirmed burn, 640x512 holdout, 0 holdout negatives -> H1 is recall-only and box-IoU numbers are weak; the FireMan VAL negatives are one pre-/off-burn segment of one video.
- **Sheffield is one 12-minute session** with fragmented sub-box labels; H3 is within-incident for everyone and contaminated for the data arms (the Sheffield data agent used all exported frames; discovered at lockbox build).
- **Ensemble gains are site-dependent and calibration does not transfer**; the +2.8 pt macro is a well-supported marguerite gain plus a within-noise cabanelle gain; RF-DETR-L alone is best on cabanelle. On the held-out H2 the ensemble is below the best single model at every FP level <= 10% (§4, §7); GPU latency is copied from v3/v4 reports, not re-measured.
- **Segmentation GT is 98% SAM pseudo-masks**; IoU against them measures SAM agreement; the 7 human masks say diffuse haze is under-segmented; one clear-cut flight defeats every model's negatives.
- **B200 high-res result is one run per resolution** (no seeds) with the head's anchors/RoI sampling left at their 1280 tuning; the same-corpus 1280 control isolates resolution, but the gap to v4 B4 still mixes AuSmoke removal with hardware; the probe's toy `nan` val losses remain unexplained (the real runs had finite metrics at every eval).
- **No new GPU latency, no selective execution, no learned fusion in serving**; ACCURATE on CPU is 5.8-12.5 s/frame.
- **Labels:** nothing in v5b was human-reviewed by us; all "negatives" are author statements (FireMan smoke_presence=no, Sheffield empty files, pyro-sdis label omissions known).
- **Permissions:** FireSpot and WSDataset remain unusable; AuSmoke's prior use is disclosed, not extended; Qwen-27B bf16 remains untested.

## 12. What we would do next

1. **Use D3's mechanism on the right material:** unlabelled *fixed-camera* positive sequences (sdis-style cameras, FIgLib-like but licensed) where the teachers can add small-plume boxes; verify a sample by humans before training.
2. **Seeds for everything that is compared:** A and B now have three; C/D/D2/D3 and the B200 pair have one — and run the deployment candidate's seed repeats through the H1 check before relying on a per-checkpoint margin.
3. **Unblock WSDataset** (one Kaggle token -> 13k author negatives + author boxes) and **e-mail FireSpot's authors** for a licence; ask FireMan's authors for the video->burn mapping (releases burn B if it is not Ruokolahti).
4. **Per-camera calibration as a product feature** (the threshold-transfer result makes it mandatory), then an ensemble test with selective execution (YOLO gate -> DINO on candidates) to bring ACCURATE under ~50 ms/frame on one GPU.
5. **B200:** same-corpus 1280 control for the high-res run (L40S node), reproduce the toy `nan`, then the Qwen-27B bf16 1 MP arm (<= 4 node-h) to close the v2 quantisation/resolution confound.
6. **Segmentation:** hard-negative clear-cut frames, human masks for a thin-smoke eval set, mask-to-box auxiliary loss on Subset-A boxes; keep it as an overlay.
7. **Lockbox hygiene:** build eval packages before data agents build corpora (the H3 contamination was avoidable); record H3 roster contamination per system in `reports/v5b/test/ROSTER_V5B.json`.
